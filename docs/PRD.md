| 项目 | 内容 |
|---|---|
| 产品名称 | StudyPilot |
| 产品形态 | Web 端 AI 学习教练 |
| 文档版本 | v0.1 |
| 当前阶段 | MVP 需求定义 |
| 目标用户 | 使用英文课程资料的国际研究生 |
| 首个验证用户 | 比利时鲁汶高校在读研究生 |

## 1. 产品概述

### 1.1 产品定位

StudyPilot 是一款面向国际研究生的双语 AI 学习教练。学生上传课程讲义和阅读材料后，系统基于课程资料提供带出处的知识讲解、针对性练习、答案批改、薄弱点诊断和复习建议。

StudyPilot 的核心价值不是代替学生完成课程作业，而是建立“理解—练习—评估—复习”的个性化学习闭环。

### 1.2 一句话介绍

上传英文课程资料，用中文辅助理解、用英文练习作答，并根据薄弱点持续改进。

### 1.3 产品目标

MVP 需要验证三个核心假设：

1. 基于课程材料且标注来源的回答，比通用聊天机器人更适合课程学习。
2. 根据指定章节生成练习并按评分标准批改，能够帮助学生发现知识盲点。
3. 保存薄弱知识点并用于下一轮练习，能够形成有价值的个性化体验。

### 1.4 非目标

MVP 不以以下能力为目标：

- 替学生完成可直接提交的作业、论文或考试答案。
- 覆盖所有专业和所有题型。
- 提供教师端、班级管理或多人协作。
- 替代学校官方课程平台。
- 提供实时课堂录音、视频理解或移动端 App。
- 保证模型回答等同于教师或学校的最终判定。

## 2. 背景与问题

国际研究生经常使用非母语学习高密度课程内容，常见问题包括：

- 英文课件、论文和讲义阅读耗时较长。
- 通用大模型可能给出正确但不符合本课程范围的解释。
- 学生难以快速定位回答所依据的课件页码或原文。
- “看懂了”不等于能够在考试中独立作答。
- 缺少稳定、明确的练习评分标准。
- 学习资料、答题记录和薄弱知识点分散。
- 学生用中文理解概念后，仍难以用准确英文作答。

StudyPilot 通过课程级 RAG、练习生成、评分量表和学习记忆解决以上问题。

## 3. 目标用户

### 3.1 核心用户画像

**国际研究生**

- 正在欧洲高校攻读英文授课硕士或博士课程。
- 日常阅读英文 slides、论文、syllabus 和作业说明。
- 希望用中文辅助理解，但需要用英文参加考试或完成表达。
- 同时学习多门课程，复习时间有限。
- 已使用过通用大模型，但担心幻觉、出处不清和回答范围偏离课程。

### 3.2 典型使用场景

1. 课前预习：快速了解某一 Lecture 的概念结构。
2. 课后复习：针对不理解的公式或理论进行双语解释。
3. 考试准备：限定章节生成练习题并用英文作答。
4. 答案诊断：根据 rubric 分析遗漏、错误和表达问题。
5. 学习规划：根据考试日期和薄弱点安排复习顺序。

## 4. 核心产品原则

### 4.1 资料优先

涉及课程内容时，优先根据用户上传的资料回答。模型的通用知识只能作为补充，并且必须明确标识。

### 4.2 可追溯

知识讲解、题目和批改反馈应尽可能关联原始文件、章节和页码。系统找不到足够证据时，应明确说明，而不是编造出处。

### 4.3 学习而非代写

系统可以解释知识、提供分级提示、生成相似练习和反馈，但不得把代写可提交成果作为核心能力。

### 4.4 双语协同

允许课程材料为英文、概念解释为中文、专业术语保留英文、练习回答使用英文、批改反馈使用中文。

### 4.5 个性化可控

系统可以保存学习偏好与薄弱点，但用户必须能够查看、修改或清除这些信息。

## 5. MVP 范围

### 5.1 P0：MVP 必须完成

- 创建、查看、编辑和删除课程。
- 上传 PDF、Markdown 和 TXT 课程资料。
- 显示资料处理状态与失败原因。
- 按课程建立隔离的知识索引。
- 基于课程资料进行带来源问答。
- 支持中文、英文和中英双语解释。
- 按章节、难度、题型和数量生成练习题。
- 支持选择题、简答题和概念解释题。
- 使用预先生成的 rubric 批改简答题。
- 展示得分、正确点、遗漏点、错误点和复习来源。
- 记录知识点掌握状态和历史练习结果。
- 根据薄弱知识点推荐下一轮练习。
- 提供基本的学术诚信提示。

### 5.2 P1：MVP 完成后增强

- PPTX、DOCX 文档解析。
- 基于考试日期生成周学习计划。
- 间隔重复复习提醒。
- 题目收藏、错题本和重新作答。
- 多文档对比和论文阅读模式。
- 回答流式输出。
- 学习报告导出。
- 更细粒度的费用和 Token 使用统计。

### 5.3 暂不实现

- OCR 扫描件识别。
- 视频和音频课程处理。
- 教师端和班级管理。
- 多人共享课程空间。
- 学校 LMS 集成。
- 原生移动端应用。
- 在线监考场景中的实时答题协助。

## 7. 核心用户流程

### 7.1 首次使用

```text
进入产品
→ 创建课程
→ 填写课程名称、考试日期和学习目标
→ 上传课程资料
→ 等待解析与索引
→ 进入课程 AI 导师
→ 提问或开始诊断练习
```

### 7.2 课程资料问答

```text
选择课程
→ 输入问题并选择回答语言
→ 系统识别问题与检索范围
→ 检索相关资料片段
→ 对结果去重、排序和过滤
→ 生成回答
→ 展示文件名、页码和引用片段
→ 用户继续追问或将知识点加入练习
```

### 7.3 练习与批改

```text
选择章节、题型、难度和数量
→ 系统检索课程资料
→ 生成题目、参考答案和 rubric
→ 用户作答
→ 系统按 rubric 评分
→ 展示反馈和资料出处
→ 更新知识点掌握度
→ 推荐复习内容或下一道题
```

### 7.4 个性化复习

```text
读取历史练习结果
→ 找出低掌握度或反复出错的知识点
→ 推荐资料和练习范围
→ 用户完成新一轮练习
→ 更新掌握度与错误类型
```

## 8. 功能需求

### 8.1 课程管理

#### 用户需求

用户需要按课程组织资料、对话、练习和学习进度，防止不同课程内容混淆。

#### 功能要求

- 创建课程时填写课程名称。
- 可选填写课程代码、学校、学期、考试日期、目标成绩和课程描述。
- 用户可以编辑课程信息。
- 删除课程前必须二次确认。
- 删除课程时应清理其文档索引、对话和练习记录。
- 课程列表显示资料数量、最近学习时间和总体进度。

#### 验收标准

- 用户可以成功创建并进入一门课程。
- 两门课程的资料、问答和练习数据相互隔离。
- 删除课程后不能再检索到该课程的内容。

### 8.2 资料上传与处理

#### 功能要求

- MVP 支持 PDF、MD、TXT。
- 单个文件大小上限暂定为 30MB。
- 文件状态包括：等待处理、处理中、可用、失败。
- 文档处理保留文件名、页码、章节、资料类型和上传时间。
- 用户可为资料选择类型：Lecture、Reading、Assignment、Past Exam、Notes、Other。
- 重复上传相同文件时提醒用户。
- 解析失败时显示可理解的错误原因并允许重试。
- 用户可以删除单份资料及其索引。

#### 分块要求

每个知识片段至少关联：

- `user_id`
- `course_id`
- `document_id`
- `document_type`
- `source_file`
- `page_number`
- `section_title`
- `language`
- `chunk_index`

#### 验收标准

- 上传成功后可在资料列表看到处理状态。
- 可用资料能够被课程问答检索。
- 引用能够定位到正确文件，PDF 应尽可能显示正确页码。
- 删除文档后，相关内容不再出现在新回答中。

### 8.3 AI 导师问答

#### 功能要求

- 用户可以限定课程、资料类型、文档或章节范围。
- 回答语言支持中文、英文、中英双语。
- 中英双语模式默认用中文解释，并保留英文专业术语。
- 回答包含正文和来源列表。
- 来源至少展示文件名、页码或章节、相关片段。
- 明确区分“课程资料内容”和“模型补充说明”。
- 证据不足时回答“不足以根据当前资料确认”，并建议补充资料或调整问题。
- 支持当前课程内的多轮追问。
- 用户可以对回答标记“有帮助”或“有问题”。

#### 回答模式

- 简洁解释：给出直接、短篇的核心解释。
- 深入讲解：包含直觉、定义、公式、例子和常见误区。
- 苏格拉底模式：优先通过问题引导学生思考。
- 考试模式：使用适合英文考试作答的结构进行讲解。

#### 验收标准

- 有相关资料时，回答至少包含一个有效来源。
- 不得生成不存在的文件名或页码。
- 切换课程后，不得引用其他课程的私有材料。
- 用户指定“只根据 Lecture 1–3”时，检索不得超出该范围。

### 8.4 练习题生成

#### 输入项

- 课程和资料范围
- 题型
- 难度：基础、中等、进阶
- 题目数量
- 题目语言
- 是否优先覆盖薄弱知识点

#### 题型

- 单项选择题
- 简答题
- 概念解释题

#### 每道题保存

- 题目正文
- 题型和难度
- 对应知识点
- 资料来源
- 参考答案
- 评分 rubric
- 生成时间和生成模型

#### 生成规则

- 题目必须能够从选定资料范围中得到支持。
- 不得在题目正文中泄露答案。
- 选择题的干扰项应合理但不能含糊到存在多个正确答案。
- 简答题必须生成结构化评分标准。
- 不允许仅因措辞与参考答案不同而判错。

#### 验收标准

- 用户能按指定范围生成练习。
- 每道题至少关联一个来源片段。
- 生成的题目可以独立保存和提交答案。
- 无足够资料时不生成低可信度题目，并说明原因。

### 8.5 答案批改

#### 评分维度

- 事实正确性
- 关键概念覆盖率
- 推理完整性
- 与课程材料的一致性
- 是否直接回答题目
- 英文表达清晰度（仅在启用语言反馈时计入或单独展示）

#### 输出内容

- 总分和各维度得分
- 已正确覆盖的要点
- 缺失要点
- 错误或存在风险的表述
- 可执行的改进建议
- 参考答案或参考结构
- 推荐复习的来源页码

#### 评分规则

- 批改必须优先依据题目生成时保存的 rubric。
- 不因学生使用不同但正确的表述而扣分。
- 资料不能支持的判断应标记为不确定。
- 语言错误和知识错误分开反馈。
- 用户可以申请重新评估，并说明异议。

#### 验收标准

- 同一道题、相同答案的重复评分应基本稳定。
- 每项主要扣分都必须关联 rubric 或资料证据。
- 批改结果能被写入学习记录。

### 8.6 学习画像与薄弱点

#### 保存内容

- 默认解释语言和答题语言
- 喜欢的讲解风格
- 课程目标和考试日期
- 知识点掌握度
- 常见错误类型
- 最近练习结果
- 推荐复习知识点

#### 掌握度建议

每个知识点记录：

- 最近得分
- 平均得分
- 尝试次数
- 最近练习时间
- 掌握状态：未练习、薄弱、学习中、已掌握

MVP 可以采用规则计算掌握度，不要求训练推荐模型。

#### 用户控制

- 用户可以查看系统记录的学习画像。
- 用户可以修改语言和讲解偏好。
- 用户可以删除某项薄弱点或清除学习历史。

#### 验收标准

- 完成练习后，对应知识点状态会更新。
- 选择“针对薄弱点练习”时，系统优先覆盖低掌握度主题。
- 清除记录后，后续推荐不再使用被删除的信息。

### 8.7 学术诚信

#### 基本规则

- 允许解释概念、总结资料、生成练习和提供分级提示。
- 对明显可提交的作业请求，优先提供思路、检查清单或类似练习。
- 不虚构引用、数据、实验结果或用户未完成的研究过程。
- 对考试中的实时作弊请求不提供直接答案。
- 学术诚信提示应简短，并继续提供合适的学习帮助。

## 9. Agent 设计

用户始终面对统一的 StudyPilot 助手，Agent 是后台能力模块。

| Agent | 职责 | 典型输出 |
|---|---|---|
| Tutor Agent | 课程问答、双语解释、引导学习 | 带来源讲解、分级提示 |
| Quiz Agent | 根据课程范围和薄弱点生成题目 | 题目、答案、rubric、来源 |
| Evaluator Agent | 根据 rubric 与资料批改答案 | 分数、证据、错误和改进建议 |
| Planner Agent | 根据目标、时间和掌握度规划学习 | 学习任务、优先级、复习建议 |

### 9.1 路由原则

- 单一请求路由给一个主要 Agent。
- 复杂任务可以串行调用，例如 Quiz → Evaluator → Planner。
- 结构化数据库查询和文档检索通过工具执行，不由模型猜测。
- Agent 失败时返回可理解的降级结果，不得伪造成功状态。

## 10. RAG 需求

### 10.1 检索范围

- 默认仅检索当前用户和当前课程。
- 支持按资料类型、文件、章节和页码范围过滤。
- 对多轮追问，应结合当前问题与必要的对话上下文进行查询改写。

### 10.2 检索流程

```text
用户问题
→ 查询理解与范围识别
→ 元数据过滤
→ 向量召回与关键词召回
→ 合并去重
→ 重排
→ 证据充分性判断
→ 基于证据生成回答
```

### 10.3 引用要求

- 引用对象必须来自实际检索结果。
- 引用显示文件名和页码；无法获取页码时显示章节或片段位置。
- 前端允许用户展开查看引用片段。
- 模型补充知识不能伪装成课程资料引用。

### 10.4 无答案处理

当检索证据不足时：

1. 明确当前资料不足。
2. 说明检索过的范围。
3. 建议用户上传资料、放宽范围或重新描述问题。
4. 如提供通用知识补充，必须明确其不是来自课程资料。

### 12.4 AI 导师

建议布局：

- 左侧：资料范围和回答模式。
- 中间：对话区。
- 右侧：来源、相关知识点和加入练习入口。

### 12.5 练习中心

支持：

- 配置练习范围和难度
- 逐题作答
- 提交与查看反馈
- 查看 rubric 和来源
- 针对错误重新练习

### 12.6 学习进度

显示：

- 知识点掌握状态
- 历史得分趋势
- 常见错误类型
- 最近练习记录
- 推荐复习主题

## 13. 非功能需求

### 13.1 性能

- 普通页面接口 P95 响应时间目标低于 1 秒，不含文档处理和 LLM 调用。
- 文档上传后立即返回任务状态，不阻塞等待全部索引完成。
- AI 首次完整响应目标低于 15 秒；后续可增加流式输出改善体验。
- 检索结果应支持缓存，但文档删除后必须正确失效。

### 13.2 可靠性

- LLM、Redis 或向量库不可用时返回明确错误或有限降级结果。
- 文档处理任务可重试，并避免重复写入相同片段。
- Agent 和工具调用记录成功、失败、耗时和降级状态。

### 13.3 隐私与安全

- 不在日志中记录 API Key、完整文档正文或敏感用户答案。
- 所有私有资料查询必须带 `user_id` 和 `course_id` 过滤。
- 文件上传校验扩展名、MIME 类型和大小。
- 用户删除资料后应清理原文件、索引和关联引用。
- `.env` 不得提交到版本库。

### 13.4 可解释性

- 回答、题目和批改尽可能关联证据。
- 评分结果展示评分维度与扣分原因。
- 系统不得把模型推断描述为课程资料中的确定事实。

## 14. 成功指标

### 14.1 产品指标

- 课程创建完成率。
- 文档成功解析率。
- 首次上传后完成第一次提问的比例。
- 完成一组练习的比例。
- 用户在一周内再次学习的比例。
- “回答有帮助”的比例。

### 14.2 AI 质量指标

- 引用有效率：引用能够对应实际文件和位置。
- 回答忠实度：回答中的课程事实能够被检索证据支持。
- 检索相关性：召回片段与问题的相关程度。
- 题目可回答率：题目能从指定课程资料中得到支持。
- 评分一致性：相同答案重复评分的差异。
- 约束遵循率：语言、章节、题型和难度要求是否得到执行。

### 14.3 MVP 建议验收目标

以下指标是开发验收目标，不是未经验证的对外宣传数据：

- 支持的文本型 PDF、MD、TXT 解析成功率达到 95%。
- 测试集中的引用有效率达到 95%。
- 测试集中的跨课程数据泄漏为 0。
- 有充分资料的问题中，回答忠实度人工评分达到 4/5。
- 练习题可回答率达到 90%。
- 相同答案重复评分差异不超过总分的 10%。

## 15. 评测方案

### 15.1 RAG 问答评测集

为首个课程准备至少 30 个问题：

- 直接事实题
- 跨页综合题
- 概念比较题
- 公式解释题
- 无答案题
- 限定章节题

评估检索相关性、回答正确性、忠实度、引用准确性和无答案处理。

### 15.2 出题评测集

从不同章节生成至少 30 道题，人工检查：

- 是否在课程范围内
- 是否存在明确答案
- 难度是否合理
- 选择题是否只有一个最佳答案
- rubric 是否覆盖关键知识点

### 15.3 批改评测集

为至少 10 道简答题准备优秀、一般、错误三档标准答案，检查：

- 得分顺序是否合理
- 主要错误是否被识别
- 正确的不同表达是否被接受
- 相同答案重复评估是否稳定

## 16. 技术约束与复用范围

MVP 基于现有 EchoMind Python 框架改造：

- FastAPI 作为后端框架。
- ChromaDB 作为课程资料向量库。
- Redis 保存短期对话状态和缓存。
- AgentOrchestrator 负责 Tutor、Quiz、Evaluator、Planner 的路由与组合。
- SkillLoader 加载教学、出题、评分和学术诚信规则。
- ToolManager 负责检索工具的超时、缓存、熔断和降级。
- Prometheus 记录接口、Agent、检索和 LLM 指标。
- Docker Compose 提供本地部署环境。

客服领域的意图、提示词、演示数据和评测集仅作为代码模板，不进入最终产品。

## 18. MVP 发布标准

满足以下条件时，可认为 MVP 完成：

1. 用户可以创建至少两门相互隔离的课程。
2. 用户可以上传 PDF、MD 或 TXT，并查看处理状态。
3. 用户可以针对指定课程资料提问并获得真实可点击或可展开的来源。
4. 系统在资料不足时不会伪造课程依据。
5. 用户可以生成至少三种题型的练习。
6. 用户可以提交简答题并获得基于 rubric 的反馈。
7. 系统会保存练习结果并识别至少一种薄弱知识点。
8. 用户可以针对薄弱知识点生成下一轮练习。
9. 系统具备基本错误处理、日志、监控和数据隔离。
10. 核心流程具备自动化测试和离线评测结果。

## 19. 待确认事项

以下事项应在技术设计或开发前逐步确认：

- 第一门用于开发和演示的课程。
- 首选 LLM Provider 和可接受的调用成本。
- MVP 是否需要账号登录，或先采用单用户模式。
- 是否允许保存上传文件原文，还是只保存解析文本和索引。
- 页码引用需要跳转 PDF 预览，还是第一版仅显示页码和片段。
- 第一版前端采用现有 Vue 控制台改造，还是重新设计界面。
- 学习进度是否需要日历式计划，还是先提供主题优先级列表。
