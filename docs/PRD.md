| 项目 | 内容 |
|---|---|
| 产品名称 | StudyPilot |
| 产品形态 | Web 端双语 AI 学习教练 |
| 目标用户 | 使用英文课程资料的国际研究生 |

> 实现细节与代码见仓库其余部分；实测数据见 [`tests/evals/`](../tests/evals/)。

## 1. 产品定位

StudyPilot 面向国际研究生。学生上传课程讲义与阅读材料后，系统**只基于这些资料**提供带出处的知识讲解、针对性练习、按评分标准批改、薄弱点诊断与复习安排。

一句话：**上传英文课程资料，用中文辅助理解，用英文练习作答，并按薄弱点持续改进。**

核心价值不是替学生完成课程作业，而是建立「理解—练习—评估—复习」的个性化学习闭环。

---

## 2. 背景与问题

国际研究生用非母语学习高密度课程内容，反复遇到七个问题：

1. 英文课件、论文、讲义阅读耗时长。
2. 通用大模型给出的解释**正确但不属于本课程范围** —— 用了课上没讲的定义或记号。
3. 难以定位回答依据的课件页码与原文，无法核对。
4. 「看懂了」不等于能在考试中独立作答。
5. 缺少稳定、明确的练习评分标准。
6. 学习资料、答题记录与薄弱知识点分散在各处。
7. 用中文理解了概念，仍难以用准确英文作答。

其中第 2、3 条是通用聊天工具在学习场景下的**结构性缺陷**：它优化的是「答得像」，而学习场景需要的是「答得有据、且在范围内」。这是本产品成立的前提。

---

## 3. 目标用户与场景

### 3.1 用户画像

**国际研究生**

- 在欧洲高校攻读英文授课硕士或博士。
- 日常阅读英文 slides、论文、syllabus 与作业说明。
- 希望用中文辅助理解，但需要用英文参加考试与表达。
- 同时修多门课，复习时间有限。
- 用过通用大模型，但担心幻觉、出处不清、范围偏离课程。

### 3.2 典型场景

| # | 场景 | 用户想要的 |
|---|---|---|
| 1 | 课前预习 | 快速了解某一 Lecture 的概念结构 |
| 2 | 课后复习 | 对不理解的公式或理论做双语解释 |
| 3 | 考试准备 | **限定章节**生成练习并用英文作答 |
| 4 | 答案诊断 | 按 rubric 分析遗漏、错误与表达问题 |
| 5 | 学习规划 | 按考试日期与薄弱点安排复习顺序 |

场景 3 里的「限定章节」是高频且刚性的需求 —— 学生复习时按章节组织，而不是按整门课。这直接决定了检索必须支持章节级范围隔离（见 §6.2）。

## 4. 核心产品原则

五条原则用于在需求冲突时做取舍。**每条都写明了它的代价** —— 没有代价的原则不是原则。

### 4.1 资料优先

涉及课程内容时只依据用户上传的资料回答。

**代价**：资料未覆盖时会明确说「资料里没有」，而不是用通识知识补齐。牺牲「有问必答」的体验，换取学习场景不可让渡的可信度。

### 4.2 可追溯

讲解、题目、批改反馈都关联到原始文件、章节与页码，引用可展开原文并跳转到 PDF 对应页。证据不足时明确说明，不编造出处。

**代价**：回答链路更长，需要额外的引用校验与失败重试。

### 4.3 学习而非代写

系统解释知识、给分级提示、生成相似练习与反馈，但不把「代写可提交成果」作为能力。

**代价**：会拒绝一部分用户的直接诉求。因此风控必须精准 —— 误伤正常学习请求比漏放更糟（见 §7）。

### 4.4 双语协同

课程材料为英文、概念解释可为中文、专业术语保留英文、练习作答用英文、批改反馈用中文。**讲解语言与出题语言可分别设置** —— 学生常常用一种语言理解、用另一种语言考试，二者不应绑定。

### 4.5 个性化可控

系统保存学习偏好与薄弱点，但用户必须能查看、修改、删除其中任意一条。

## 5. 核心用户流程

### 5.1 首次使用

```text
创建课程 → 填写名称、考试日期、学习目标
→ 上传课程资料 → 等待解析与索引（可见进度与失败原因）
→ 进入 AI 导师 → 提问或开始诊断练习
```

### 5.2 课程资料问答

```text
选择课程与检索范围（资料 / 类型 / 页码 / 章节）
→ 输入问题并选择回答语言
→ 系统识别意图与范围 → 检索资料片段 → 去重、排序、过滤
→ 生成回答 → 展示文件名、页码与引用原文
→ 继续追问，或将该知识点转入练习
```

### 5.3 练习与批改

```text
选择章节、题型、难度、数量、出题语言
→ 系统检索资料 → 生成题目、参考答案与 rubric
→ 用户作答 → 按 rubric 逐条评分
→ 展示得分、正确点、遗漏点、错误点与资料出处
→ 更新知识点掌握度 → 推荐下一轮练习
```

### 5.4 个性化复习

```text
读取历史作答 → 找出低掌握度与反复出错的知识点
→ 结合考试日期生成可勾选的每日计划
→ 完成新一轮练习 → 更新掌握度与错误类型
```

## 6. 功能范围

### 6.1 资料管理

- 创建、查看、编辑、删除课程；设置考试日期与学习目标。
- 上传 PDF / Markdown / TXT，显示处理状态与失败原因。
- 按课程建立隔离的知识索引，跨课程不可互相检索。

### 6.2 章节结构识别

学生按章节复习，但资料表达结构的方式各不相同。系统按可信度分级识别，**识别不出时明确标记为「无结构」而不是猜一个出来** —— 猜错的分组比没有分组更有害，它会让「第四章」返回一堆无关内容而用户毫不知情。

| 优先级 | 形态 | 识别方式 |
|---|---|---|
| 1 | 编号章节 | `Chapter 3.` / `第三章` |
| 2 | 讲义分册 | 按重复出现的标题页切分 |
| 3 | Markdown | 一级 / 二级标题 |
| 4 | 均不匹配 | 整份资料记为一个部分，标记「全文」 |

资料自己声明章号时以它为准：从 `Chapter 0` 起头的教材，用户说「第一章」应落到 `Chapter 1` 而非第一个部分。

### 6.3 AI 导师问答

- 按课程、资料类型、指定文档、页码范围、章节隔离检索。
- 支持「资料1」「第二份 PDF」这类指代。
- 回答带文件名与页码引用，同页多个片段合并展示。
- 中文提问、英文资料：提问先翻译成资料语言再检索。
- 回答语言可选中文 / 英文 / 中英对照。

### 6.4 练习与批改

- 题型：单选、多选、简答、概念解释。
- 可指定章节、难度、数量与**出题语言**（独立于讲解语言）。
- 题目携带来源与 rubric；rubric 生成后不可修改，保证同一题的评分标准稳定。
- 选择题走确定性判分，不经模型；多选按 `(选对数 − 选错数) / 正确答案数` 给部分分 —— 全对全错同分会让「三对二」和瞎猜没有区别，只数选对的则全选就是满分。
- 展示逐项得分、遗漏点、错误点与复习来源；支持练习历史与错题重练。

### 6.5 学习画像与计划

- 记录知识点掌握度、得分趋势与高频错误类型。
- 按薄弱点与考试日期生成可勾选的每日复习计划。
- 用户可查看并删除画像中的**单个**薄弱点。

## 7. 学术诚信

这是本产品最难的取舍：**学生的直接诉求（给我答案）与产品不可让渡的原则（不能代做作业）正面冲突。**

处理方式是四级判定，在任何回答生成之前运行：

| 级别 | 场景 | 处理 |
|---|---|---|
| 学习允许 | 概念讲解、原理推导、练习 | 正常提供 |
| 仅提示 | 作业题求解 | 给思路与分级提示，不给可提交答案 |
| 提交风险 | 要求直接产出可提交成果 | 拒绝代写，转为引导 |
| 实时考试 | 考试进行中求解 | 拒绝，并说明原因 |

**关键约束：风控不得以牺牲核心体验为代价。** 拒绝的是「代做」，不是「学习」—— 同一次对话里，被拒绝的部分之外的合规学习需求必须照常满足。因此验收同时看两个指标：误伤率与帮助保留率（见 §9）。

---

## 8. 明确不做

以下不是「暂未实现」，而是**判断为不应由本产品承担**：

- **心理危机与情绪求助、医疗 / 法律 / 财务等专业建议、资料之外的事实性问题** —— 这类场景需要专业训练与人工介入，做一个不可靠的版本比不做更危险。系统不做识别、不做转介，只声明不在范围内。
- 替学生完成可直接提交的作业、论文或考试答案。
- 在线监考场景中的实时答题协助。
- 教师端、班级管理、多人共享课程空间。
- 替代学校官方课程平台或 LMS 集成。
- 保证模型回答等同于教师或学校的最终判定。

## 9. 验收标准与实测

产品质量必须可度量、可回归。验收标准在开发前定义，转化为**冻结的评测集**，每次迭代重跑对比基线。

| 验收项 | 目标 | 实测 | 依据 |
|---|---|---|---|
| 引用有效率 | ≥ 95% | **100%** | RAG，30 题 |
| 跨课程资料泄漏 | 0 | **0** | RAG，30 题 |
| 章节范围遵循 | ≥ 90% | **100%** | RAG，30 题 |
| 资料外问题识别 | ≥ 90% | **100%** | RAG，5 题 |
| 跨语言检索持平 | ≥ 90% | **100%** | 中英各 14 题 |
| 意图识别准确率 | ≥ 85% | **86.5%** | 路由，57 例 |
| Agent 路由准确率 | ≥ 90% | **98.1%** | 路由，57 例 |
| 换种说法后的判断一致性 | ≥ 80% | **81.8%** | 同义表达，11 组 41 条 |
| 模糊输入澄清准确率 | ≥ 90% | **100%** | 路由，57 例 |
| 显式范围保持 | 100% | **100%** | 路由，57 例 |
| 诚信判定误伤率 | 0 | **0** | 诚信，61 例 |
| 合规帮助保留率 | 100% | **100%** | 诚信，61 例 |
| 题目可回答率 | ≥ 90% | **96.7%** | 出题，30 场景 |
| 分数区间准确率 | ≥ 90% | **100%** | 批改，90 次 |
| 重复评分稳定性 | 同一答案重复评分差异 ≤ 10 分 | **100% 达标** | 批改，90 次 |
| 提示词注入抵抗 | 100% | **100%** | 注入，10 类 |

十一套版本化评测集共 348 条用例（其中 `router_intents_v1` 45 条已被 v2 取代，去重后 303 条），基线、门槛与口径见 [`tests/evals/README.md`](../tests/evals/README.md)。

**评测口径本身也被修正过。** 例如注入评测早期把「模型识破攻击、点名指出并拒绝执行」判为失败 —— 一个惩罚正确行为的指标比没有指标更糟。这类更正都记录在案。

### 产品侧观测指标

上述为质量指标；产品侧另行观测：文档解析成功率、首次上传后完成第一次提问的比例、完成一组练习的比例、一周内再次使用的比例。
